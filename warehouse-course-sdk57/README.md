# «Об’єктно-орієнтована програмна система складського обліку»

Навчальний мобільний застосунок українською мовою на React Native, Expo SDK 57, TypeScript і SQLite. Основна платформа — Android. Застосунок працює офлайн і зберігає записи у локальній `warehouse.db`.

## Запуск

Потрібні Node.js 22.13+ та Android Studio/Android Emulator або Android-пристрій із Expo Go для SDK 57. Для перевірки на реальному пристрої також можна створити development build.

```bash
npm install
npx expo install --fix
npm run android
```

З `npm start` можна відкрити QR-код у Expo Go. Для Android emulator натисніть `a` у терміналі чи виконайте `npm run android`. Перевірки: `npm run typecheck`, `npm test`. Створення Android APK: `npx eas build --platform android --profile preview` (після налаштування EAS) або `npx expo run:android` із Android SDK.

## Предметна область і вимоги

Складський облік описує картки товарів, місця їх зберігання й рух запасів. Користувач створює довідники категорій і типів, заводить картку з артикулом, одиницею, ціною та мінімальним залишком, реєструє надходження, видачу або переміщення. Журнал зберігає автора, дату і коментар руху. Звіти показують залишки по кожному складу, облікову вартість за поточною ціною та нестачу до мінімуму.

Функціональні вимоги: CRUD карток/складів і довідників; пошук назвою/артикулом/серійним номером; фільтри за складом, категорією та типом; залишки, журнал за періодом та видом руху; звіт і CSV; архівування без видалення історії.

## Архітектура

- `src/domain/entities.ts`: `Product`, `Category`, `EquipmentType`, `Warehouse`; валідація й зміна стану інкапсульовані в методах.
- `src/domain/operations.ts`: абстрактний `StockOperation`; `ReceiptOperation`, `IssueOperation`, `TransferOperation` перевизначають `execute`.
- `src/domain/repositories.ts`: абстракції сховища та транзакції. Предметний шар не залежить від SQL.
- `src/data/SQLiteInventoryRepository.ts`: SQLite-запити й SQL-репозиторій.
- `src/data/schema.ts`: міграція версії 0→1, індекси, обмеження та тригери.
- `src/services/InventoryService.ts`: перевірка застосункового сценарію, orchestration, архівування, звіт і безпечний запуск демоданих.
- `App.tsx`: функціональні екрани та форми, hooks для стану, Expo SQLite provider.

Складські рухи й залишки записуються через `withExclusiveTransactionAsync`. Якщо перевірка, зміна балансу або вставка журналу завершується помилкою, SQLite відкочує всю транзакцію. Завершені операції мають тільки читальні форми.

### Схема даних

`categories` і `equipment_types` мають унікальний нормалізований ключ; `warehouses` зберігає опис і прапорець архіву. `products` має зовнішні ключі, унікальні SKU і nullable унікальний serial number; ціни — integer копійки. `stock_balances` має складений первинний ключ (товар, склад) та невід’ємну кількість. `stock_operations` — append-only журнал з типом руху, датою, кількістю, обома складами, відповідальним і коментарем. Foreign keys увімкнені; тригери SQLite не дозволяють серійному обладнанню бути кількістю більше одного чи водночас на двох складах. Індекси прискорюють пошук, фільтри складу, товару, дати й типу руху. Версію контролює `PRAGMA user_version`.

## ООП на конкретних прикладах

- **Інкапсуляція:** `Product` тримає приватні поля і перевіряє їх у `update`; `Warehouse.archive(total)` забороняє архівування з залишком; `StockOperation` перевіряє додатну кількість і відповідального.
- **Наслідування:** три конкретні класи операцій успадковують `StockOperation`.
- **Поліморфізм:** `InventoryService.execute(kind, input)` створює потрібного нащадка та викликає спільний `execute(tx)`. Реалізації по-різному змінюють залишки.
- **Абстракція:** `InventoryRepository` та `InventoryTransaction` приховують SQLite. `InventoryService` отримує репозиторій через конструктор, тести підставляють in-memory транзакцію.
- **SRP:** UI приймає ввід, сервіс координує сценарії, операція містить правило руху, репозиторій зберігає дані.

## Сценарій захисту

1. У «Довідники» додати категорію «Мережеве обладнання» та тип «Маршрутизатор».
2. У «Склади» створити «Основний склад» і «Резерв».
3. У «Товари» додати «Комутатор», артикул `SW-001`, одиниця `шт`, облікова ціна 2500 грн, мінімум 2.
4. Оформити надходження 10 одиниць на основний склад.
5. Оформити видачу 3 одиниць. Спробувати видати 99 — система відмовить, баланс не зміниться.
6. Перемістити 2 одиниці на резерв. Загальний залишок залишиться 5.
7. Сформувати звіт: залишки за двома складами й сума поточної облікової вартості; поділитися CSV.

## Перевірки й обмеження

Unit-тести покривають надходження/видачу/переміщення, відмову при нестачі та некоректній кількості, серійне обладнання, звіт щодо мінімального залишку й rollback contract репозиторію. Міграція перевіряється на запуску через `SQLiteProvider`. Застосунок починає роботу з порожніми довідниками й складами; записи створюються користувачем.

Локальне середовище виконання ChatGPT може не мати Android емулятора чи SDK. Після розпакування перевірте збірку на пристрої: `npm install`, `npx expo install --fix`, `npm run typecheck`, `npm test`, `npx expo run:android`. Ціна навчальна, звіт використовує поточну облікову ціну, без бухгалтерської оцінки запасів.
